1

📍 Onde IA entra no fluxo — 3 padrões

Decidir cedo em qual padrão a IA entra. Padrão errado quebra adoção.

1ª linha

IA recebe tudo, escala exceções.

Risco alto. Exige robustez. Volume alto.

Triagem 🎯

IA categoriza e encaminha pro humano certo.

Mais seguro pra iniciar. Recomendado.

Fim do fluxo

IA resume, registra, gera follow-up.

Risco baixo. Início conservador.

💡 Recomendação para 1º projeto

Comece sempre por triagem. Migra pra 1ª linha depois de 30-60 dias com métricas boas. Pular essa cadência é receita pra incidente público.

2

🎚️ Matriz HITL em 4 níveis

HITL = Human-In-The-Loop. 4 níveis canônicos, por nível de risco do cenário.

N1

N1 — Observação

IA propõe, humano lê tudo, humano decide. Para cenários novos ou de alto risco. Modo aprendizado.

N2

N2 — Sugestão

IA propõe resposta pronta. Humano edita se quiser e envia. Padrão pra estreias de fluxo.

N3

N3 — Execução com gate

IA executa, humano aprova antes de enviar (gate). Para cenários estabelecidos. Maioria dos cenários PME chega aqui em 30-60 dias.

N4

N4 — Autônomo com auditoria

IA decide e executa. Auditoria por amostragem (10-20% das interações). Para cenários muito estabelecidos e baixo risco.

📊 Critério de classificação

Risco × Volume = nível. Pedido R$ 50 = N4. Pedido R$ 5k = N3. Cancelamento de cliente fiel = N2. Cliente novo PJ = N1.

3

🚨 Gatilhos de escalonamento

Lista explícita de gatilhos. Sem gatilhos, agente inventa ou trava.

💰 Gatilhos quantitativos

Pedido > R$ X · desconto > Y% · prazo de pagamento > Z dias · quantidade > W unidades.

📝 Gatilhos qualitativos

Palavras "cancelar", "reclamar", "processo", "tribunal", "advogado". Cliente novo PJ. Cliente inadimplente.

🤖 Gatilhos de confiança

Confiança do modelo < threshold. Resposta acessou RAG e não achou. Pergunta ambígua (2+ interpretações possíveis).

⚙️ Gatilhos técnicos

API do Bling retorna erro. Pagamento PIX falha 3x. Cliente sem cadastro completo. ERP em manutenção.

✓ Cada gatilho tem roteamento

Pedido > R$ 5k → gerente comercial. Reclamação → sócio. Erro técnico → equipe TI. Definir quem recebe cada tipo, com SLA de retorno.

4

🛟 Fallback quando agente trava

Quando agente não sabe responder, não inventa. Diz frase padrão de recusa e cria ticket.

✓ Fallback bom

"Deixa eu verificar essa informação com a equipe. Te retorno em até 30 min com a resposta correta. Combinado?"
  • • Honesto
  • • Educado
  • • Define expectativa
  • • Cria ticket automático

✗ Fallback ruim

"Acho que sim..." / "Provavelmente..." / Resposta inventada
  • • Alucinação
  • • Cliente perde confiança
  • • Sem rastreamento
  • • Operador não sabe

🎯 Fluxo do fallback

  1. Agente detecta baixa confiança ou erro
  2. Envia frase padrão pro cliente
  3. Cria ticket no sistema com contexto
  4. Notifica humano via Telegram/WhatsApp
  5. Humano responde dentro do SLA
  6. Caso entra no histórico pra alimentar bateria de testes
5

🔌 Plano de integrações

Documenta integrações necessárias: WhatsApp Cloud API, ERP REST, Supabase pgvector, PIX/NF-e. Cada uma com escopo, credenciais e 1 chamada real testada.

⚠️ Erro caro: não validar com chamada real

"API do Bling funciona" no papel ≠ funciona pra esse cliente. Permissões podem estar limitadas. Endpoint Y pode não existir no plano dele. Faz 1 GET real de cada API antes de fechar a fase P. Bug de credencial em deploy custa 2-3 dias e gera incidente público.

6

⚖️ RIPD enxuto (LGPD-PME)

Relatório de Impacto à Proteção de Dados enxuto para microempresa (ANPD 2/2022). 1-2 páginas. Vai pro Pacote de Contexto. Exit-gate da fase P.

📋 Estrutura do RIPD enxuto

  • • Identificação: empresa, CNPJ, responsável legal
  • • Tratamento: qual dado é coletado, processado, armazenado
  • • Base legal: consentimento, execução de contrato, legítimo interesse
  • • Retenção: 12-24 meses padrão · log de conversa criptografado
  • • Direitos do titular: acesso, correção, exclusão, portabilidade
  • • Canal de exercício: e-mail de contato + prazo de resposta (15 dias)
  • • Notificação de incidente: 72h ao titular e ANPD se grave

✓ RIPD enxuto OK

  • • 1-2 páginas
  • • Linguagem clara
  • • Cliente entende e assina
  • • Revisão anual

✗ RIPD acadêmico

  • • 20 páginas com jargão
  • • Cita 50 artigos
  • • Cliente não lê
  • • Não vira operacional

⚖️ ANPD 2/2022 — Regime simplificado

Microempresa e EPP: dispensa de DPO, registro enxuto, prazos dobrados. Você se posiciona como parceiro de conformidade — diferencial comercial.
